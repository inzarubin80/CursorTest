При работе с кодом 1С (BSL) придерживайся следующего.

**Имена**
- Переменные, процедуры, функции — от терминов предметной области, «говорящие»; каждое слово с прописной, без пробелов (Перем КоличествоПачекВКоробке).
- Не начинать с подчеркивания; не односимвольные (кроме счётчиков циклов). Флаги — как истинное значение (ЕстьОшибки, ЭтоТоварТара).
- Процедуры — от неопределённой формы глагола (ЗагрузитьКонтрагента). Функции — от возвращаемого значения (ПолноеИмяПользователя), для создания — с «Новый» (НовоеПолеФормы), для проверки — «Это»/причастие (ДокументПроведен). Не дублировать тип в имени (ИменаРолейСПравомДобавления, не ПолучитьМассивРолей...).

**Параметры процедур и функций**
- Имена от терминов; порядок: от общего к частному; необязательные после обязательных. Не более ~7 параметров, не более ~3 со значением по умолчанию. Много параметров — объединять в Структуру или разбивать на функции.
- Не передавать конфигурацию через переменные модуля/реквизиты формы. Не пропускать обязательные параметры. При вызове не делать глубоко вложенных вызовов и не передавать внутрь громоздкий Новый Структура(...) — выносить в переменные. Без пробелов перед/после скобок и перед запятыми: НовоеПолеФормы(ИмяПоля, ТипПоля).

**Комментарии к процедурам и функциям**
- Экспортные (программный интерфейс) — комментировать обязательно. Остальные — по необходимости. Описание начинать с глагола (Возвращает…, Проверяет…); не дублировать имя процедуры. Секции: Описание, Параметры (Имя - Тип - пояснение), Возвращаемое значение, Пример. Для Структура/ТаблицаЗначений — ссылка на функцию-конструктор (см. Модуль.ФункцияКонструктор). Избегать пустых комментариев («Обработчик ПриОткрытии»).

**Структура модуля**
- Порядок: заголовок → переменные → программный интерфейс (экспорт) → обработчики событий → служебные процедуры и функции → инициализация. Оформлять в #Область … #КонецОбласти. Пустых областей не оставлять. Обработчики событий — каждый свой; общую логику выносить в отдельную процедуру и вызывать из обработчиков.

**Конструкции языка**
- Ключевые слова канонически (КонецЕсли, не конецЕсли). Не сравнивать булево с Истина/Ложь (Если ЭтоНовый() Тогда). Длинные условия — в переменную, затем сравнение. Использовать системные наборы (Символы.ПС вместо Символ(10)).

**Переносы**
- Строка до 120 символов. Знаки операций при переносе — в начале новой строки. Параметры вызова — выравнивать по первому параметру или отступом. В Если — каждое условие с новой строки, И/ИЛИ в начале строки.

**Структуры и таблицы как параметры**
- Для сложных параметров — функция-конструктор, возвращающая структуру-заготовку или пустую ТЗ с колонками. Вызывающий код заполняет и передаёт. В вызывающем коде не добавлять лишние свойства/колонки сверх конструктора.

**Коллекции и производительность**
- ТаблицаЗначений: при многократном поиске (от ~1000 строк или много вызовов) — индексировать колонки с хорошей селективностью. Найти по нескольким колонкам — использовать НайтиСтроки, состав индекса должен совпадать со структурой поиска; Найти по нескольким колонкам индекс не использует. Копирование строк между ТЗ произвольной структуры — ЗаполнитьЗначенияСвойств(СтрокаПриемника, СтрокаИсточника), не перебор колонок. Большой массив поиска — Соответствие или индексированная ТЗ вместо перебора.

**Регистры сведений**
- Чтение без изменения — запросом. РегистрСведенийМенеджерЗаписи — только при отборе по всем измерениям. Иначе — РегистрСведенийНаборЗаписей (заполнить, записать набором).

Полные тексты стандартов — в `.continue/rules-reference/itc/` (не подгружаются как правила; при необходимости открыть вручную).
