# MCP 1C Structure (Java)

MCP-сервер для доступа к структуре конфигурации 1С: поиск объектов (нечёткий по имени/синониму), карточка объекта с реквизитами и табличными частями. Реализация на **Java** без внешних БД: данные загружаются из файла **СтруктураБазыДанных.xml** (выгрузка структуры конфигурации 1С в XML).

## Для разработчика 1С

Сервер даёт ИИ (например, в Cursor) доступ к **метаданным** вашей конфигурации: по запросу можно искать объекты (документы, справочники, регистры, константы и т.д.), получать полное описание объекта — **реквизиты** и **табличные части** с типами и синонимами, а также список мест, где объект используется как **тип** (в реквизитах, измерениях, ресурсах, колонках ТЧ).

**Источник данных** — файл выгрузки «Структура базы данных» в XML. Его можно получить из конфигуратора 1С: **Конфигурация → Сравнить, объединить с конфигурацией из файла** или через выгрузку конфигурации в файлы; в выгрузке будет файл `СтруктураБазыДанных.xml`. Альтернативно — выгрузка через EDT или другие средства, если они формируют такой же XML.

**Идентификаторы объектов** в ответах сервера соответствуют типам метаданных 1С:
- `doc.ИмяДокумента` — документ
- `cat.ИмяСправочника` — справочник
- `inforeg.ИмяРегистра` — регистр сведений
- `accreg.ИмяРегистра` — регистр накопления
- `const.ИмяКонстанты` — константа (из набора констант)
- `enum.ИмяПеречисления` — перечисление
- и т.д.

Поиск ведётся по **имени** и **синониму** объекта (нечёткое совпадение). Результаты **structure_get_object** содержат реквизиты шапки (`props`) и табличные части (`tabularSections`) с колонками — так же, как в метаданных конфигурации.

## Требования

- **Java 17+**
- **Файл СтруктураБазыДанных.xml** — выгрузка структуры базы данных конфигурации 1С в формате XML.

## Сборка

```bash
cd java
./mvnw clean package
# или: mvn clean package
```

Исполняемый JAR: `java/target/mcp-1c-structure-0.1.0-all.jar`

## Запуск

**Режим stdio (по умолчанию):**

```bash
java -jar java/target/mcp-1c-structure-0.1.0-all.jar
```

Указать путь к XML (загрузка при первом обращении к данным):

```bash
export MCP_1C_STRUCTURE_XML_PATH=/path/to/СтруктураБазыДанных.xml
java -jar java/target/mcp-1c-structure-0.1.0-all.jar
# или:
java -jar java/target/mcp-1c-structure-0.1.0-all.jar --xml-path /path/to/СтруктураБазыДанных.xml
```

**Режим HTTP:**

```bash
java -jar java/target/mcp-1c-structure-0.1.0-all.jar --http
# порт по умолчанию 8080; другой порт: --http --port 9090 или MCP_HTTP_PORT=9090
```

URL сервиса: `http://localhost:8080/mcp`

## Откуда берутся данные

- **Ленивая загрузка:** если при запуске задан `MCP_1C_STRUCTURE_XML_PATH` или `--xml-path` (путь к файлу СтруктураБазыДанных.xml), данные читаются при первом вызове любого инструмента, требующего данных.
- **Явная загрузка:** инструмент **structure_load_structure_xml** — параметр `xmlPath` (путь к файлу СтруктураБазыДанных.xml). Можно вызывать для смены источника без перезапуска сервера.

## Инструменты (Tools)

### 1. structure_search

Поиск объектов метаданных по запросу.

- **Параметры:**
  - **query** (обязательный) — строка поиска;
  - **type** — фильтр по типу (Document, Catalog, Constant и т.д.);
  - **limit** — макс. количество (по умолчанию 20, макс. 50);
  - **offset** — смещение для постраничной выборки.
- **Результат:** список совпадений с id, type, name, synonym.

### 2. structure_get_object

Полное описание одного объекта по идентификатору.

- **Параметры:**
  - **objectId** (обязательный) — идентификатор (например, `doc.ЗаказПациента`, `cat.МедицинскиеКарты`).
- **Результат:** объект со всеми полями: **props** (реквизиты), **tabularSections** (табличные части с колонками).

### 3. structure_list_types

Список типов метаданных и количество объектов каждого типа.

- **Параметры:** нет.
- **Результат:** типы (Document, Catalog, Constant и т.д.) и число объектов по каждому типу.

### 4. structure_load_structure_xml

Загрузить снимок из XML «Структура базы данных» (выгрузка конфигурации 1С в формате XML). У объектов заполняются **реквизиты** (props) и **табличные части** (tabularSections); поле content (markdown) отсутствует.

- **Параметры:**
  - **xmlPath** (обязательный) — путь к файлу `СтруктураБазыДанных.xml`.
- **Результат:** подтверждение загрузки, objectCount, configName, source `structure-xml`. После вызова **structure_get_object** возвращает объекты с полями **props** и **tabularSections**.

## Формат «Структура базы данных» (XML)

Файл **СтруктураБазыДанных.xml** — выгрузка структуры конфигурации 1С в XML. Содержит:

- **Конфигурация** — корневой элемент с атрибутом `Имя` (имя конфигурации).
- **CatalogObject.Объекты** — объекты метаданных (документы, справочники, реквизиты, примитивные типы и т.д.): Ref, Parent, Description, Имя, Синоним, Тип.
- **CatalogObject.Свойства** — реквизиты и табличные части объектов: Ref, Owner, Parent, Description, Синоним, Вид (Реквизит / ТабличнаяЧасть / Свойство), тип по ссылке в Типы/Row/Тип.

При загрузке через **structure_load_structure_xml** парсинг выполняется потоково (StAX); для прикладных объектов (Документ, Справочник, Константа, Регистры, Отчет, Обработка и т.д.) строятся идентификаторы вида `doc.ИмяДокумента`, заполняются **props** (реквизиты шапки) и **tabularSections** (табличные части с колонками). Поиск и **structure_get_object** работают с загруженным снимком.

## Структура проекта и описание файлов

```
mcp-1c-structure/
├── README.md                          # Документация (этот файл)
├── СтруктураБазыДанных.xml            # Выгрузка структуры БД конфигурации 1С (источник данных для сервера)
├── Запрос_ПациентыСМаксимальнымКоличествомЗаказов.bsl  # Пример запроса 1С (для справки, сервером не используется)
│
└── java/                              # Исходный код и сборка (Maven)
    ├── pom.xml                        # Зависимости Maven и сборка JAR
    ├── mvnw                           # Maven Wrapper (запуск без установки Maven)
    │
    ├── src/main/java/ru/mcp/structure/
    │   ├── Mcp1cStructureServer.java  # Точка входа: запуск MCP-сервера (stdio/HTTP), регистрация инструментов
    │   │
    │   ├── snapshot/                  # Модель снимка метаданных и загрузка из XML
    │   │   ├── StructureXmlLoader.java  # Парсинг СтруктураБазыДанных.xml (StAX), построение объектов с props/ТЧ
    │   │   ├── SnapshotLoader.java      # Загрузка снимка из JSON (meta, objects, relations) — для тестов
    │   │   ├── StructureObject.java     # Объект метаданных: id, type, name, synonym, props, tabularSections, usedIn
    │   │   ├── Meta.java                # Метаданные снимка: configName, source, version
    │   │   ├── Prop.java                # Реквизит/колонка: name, type, synonym
    │   │   ├── TabularSection.java      # Табличная часть: name, props (колонки)
    │   │   ├── TypeUsage.java           # Использование типа (где объект указан как тип реквизита/ТЧ)
    │   │   └── Relation.java            # Связь между объектами (from, to, kind) — для JSON-снимка
    │   │
    │   ├── store/
    │   │   └── InMemoryStore.java     # Хранилище снимка в памяти, нечёткий поиск (TF-IDF + Левенштейн)
    │   │
    │   └── search/
    │       ├── TfIdfVectors.java      # Построение TF-IDF векторов по объектам (имя+синоним, тип+синоним)
    │       └── TfIdfModel.java         # Модель для векторизации запроса при поиске
    │
    └── src/test/
        ├── java/.../Mcp1cStructureServerIntegrationTest.java  # Интеграционные тесты MCP (HTTP, инструменты, XML)
        └── resources/                  # Тестовые фикстуры (snapshot.json, rag-fixture и т.д.)
```

**Кратко по файлам:**

| Файл | Назначение |
|------|------------|
| **Mcp1cStructureServer.java** | Запуск сервера (stdio или HTTP), разбор аргументов `--xml-path` / `MCP_1C_STRUCTURE_XML_PATH`, регистрация четырёх инструментов MCP (structure_search, structure_get_object, structure_list_types, structure_load_structure_xml), ленивая загрузка XML при первом обращении к данным. |
| **StructureXmlLoader.java** | Чтение XML выгрузки структуры БД: потоковый парсинг (StAX), определение прикладных типов (Документ, Справочник, Константа, Регистры и т.д.), маппинг на префиксы (`doc`, `cat`, `const`, `inforeg`, `accreg` и др.), сбор реквизитов и табличных частей из CatalogObject.Свойства, развёртывание констант из НаборКонстант, построение usedIn (где тип используется). |
| **InMemoryStore.java** | Хранение снимка (список объектов по id), приём снимка из StructureXmlLoader, нечёткий поиск: TF-IDF + косинусная близость и/или подстрока по имени/синониму с ранжированием по Левенштейну, выдача списка типов (structure_list_types) и объекта по id (structure_get_object). |
| **StructureObject.java** | Модель одного объекта метаданных: идентификатор, тип, имя, синоним, реквизиты (props), табличные части (tabularSections), опционально usedIn, valueType для констант, content (для возможного расширения). |
| **Prop.java** | Один реквизит или колонка ТЧ: имя, тип (строка типа 1С), синоним. |
| **TabularSection.java** | Табличная часть: имя, список колонок (props). |
| **TypeUsage.java** | Запись «где используется тип»: объект (id, name, synonym), роль (requisite/dimension/resource/tabularSection), имя реквизита/ТЧ. |
| **TfIdfVectors.java** | Построение словаря термов и TF-IDF векторов по всем объектам (два представления на объект) для ранжирования при поиске. |
| **TfIdfModel.java** | Векторизация текста запроса в TF-IDF того же размера для сравнения с векторами объектов. |
| **SnapshotLoader.java** | Загрузка снимка из одного JSON-файла (meta, objects, relations) — используется в тестах. |
| **Relation.java** | Связь между объектами в JSON-снимке (from, to, kind). |
| **Meta.java** | Метаданные снимка: имя конфигурации, источник, версия. |

**СтруктураБазыДанных.xml** — ваш файл выгрузки структуры базы данных конфигурации 1С. Сервер читает только этот формат; путь к файлу задаётся переменной окружения или инструментом **structure_load_structure_xml**.

## Подключение в Cursor

**Локальный процесс (stdio):**

Укажите путь к файлу СтруктураБазыДанных.xml:

```json
{
  "mcpServers": {
    "1c-structure": {
      "command": "java",
      "args": ["-jar", "/absolute/path/to/mcp-1c-structure-0.1.0-all.jar"],
      "env": {
        "MCP_1C_STRUCTURE_XML_PATH": "/absolute/path/to/СтруктураБазыДанных.xml"
      }
    }
  }
}
```

**По URL (если сервер запущен с `--http`):**

```json
{
  "mcpServers": {
    "1c-structure": {
      "url": "http://localhost:8080/mcp"
    }
  }
}
```

При использовании URL путь к XML задаётся при запуске сервера (`MCP_1C_STRUCTURE_XML_PATH` или `--xml-path`).

### Ошибка «Failed to connect / Connection closed»

- **Пути:** в конфиге MCP должны быть **абсолютные пути** к JAR и (при необходимости) к XML. На Mac — что-то вроде `/Users/ВАШ_ЛОГИН/CursorTest/...`, на Linux — `/home/...`. Если указан путь с другой машины (например `/home/ser/...` на Mac), процесс не найдёт JAR и завершится → «Connection closed».
- **Сборка:** перед первым запуском на этой машине соберите JAR: `cd mcp-1c-structure/java && ./mvnw clean package`. Проверьте, что есть файл `java/target/mcp-1c-structure-0.1.0-all.jar`.
- **Java:** нужна Java 17+. В терминале: `java -version`.
